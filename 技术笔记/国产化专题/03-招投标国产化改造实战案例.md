## 一、iWebOA 改造对接 BSTool

iWebOA 用于提供客户端操作系统/浏览器信息，改造为接口供客户端直接调用，**脱离浏览器使用**。

**步骤**：
1. 安装驱动：新点驱动（标准版 iwebnet）**1.8.exe**。
2. 代码三处改造：
   - `com.epoint.usercontrol.EpointCa.java`：`getModel()` 中删除逐项从 dataOptions 取值赋给 CA 组件的旧逻辑（UseWebCA/UseWhite/UseCustomLayOut/UseIWebOA/ObjectName/issuerFilter 等），CA 参数统一走后台 `getCAInstance` 工厂；`decode()` 补 `@Override`。
   - `epointca.js`：
     - 初始化时将浏览器 navigator 环境信息序列化后放入 `dataOptions["Navigator"] = JSON.stringify(pcNavigator)`（appName/platform/userAgent/cpuClass 等 11 项）传给后台判断 CA 环境；
     - `useAjax` 模式（手机证书）下**不再注入**依赖 iWebOA 控件的本机信息方法（`MacAddress/IP/HostName/HardID` → `$$('iWebOA').GetMac/GetIP/GetPcName/GetHardDeskID`）；
     - `setData` 时在控件 DOM 上记录 `CAType`（`$('#'+this.id+'_epointca').attr("CAType", data.CAType)`）并补挂异步签章脚本；
     - `getValue()` 时若存在 CAType，以 `signInfo = {CAType: this.CAType}` 初始化签章信息。
   - 升级 EpointCa 的 jar 包。
3. 后台工厂（图片识别补充）：`getCAInstance(int CAType, Map<String,String> extInfo)` 按 `Class.forName("com.epoint.ztb.ca.EpointCAImpl" + CAType)` 反射实例化；当 `useAjax=true` 且实现类支持 `URLProtocolSupport` 注解（或缺省）时切换为 **`EpointCAImpl999`**。

**验证**：
- 非 IE 浏览器打开带 uc-epointca 组件页面，后台 `com.epoint.ztb.component.EpointCa.getCAInstance` 返回 **`com.epoint.ztb.ca.EpointCAImpl999`**；IE 中返回 `EpointCAImpl+CaType`。
- 生成招标文件页面，生成的 XML 中 **`<ZBFileDigitalSignal>` 有值**（数字签名生成成功；同节点还有 ZBFileDigitalSignalHash、IsHaveCAD、BiaoDuanNo、SoftVersion（如 J7.2）、PlatformCode 等）。

## 二、BSTool 支持标证通（手机/H5 签章）

标证通提供 js 写的 PDF 签章页面，使签章不再依赖 IE，并通过接口提供签章。

1. 新增 `com.epoint.EpointZBTool_BS.Generic.web.SignaturePDF.java`：`@RestController @RequestMapping("/signaturepdf")`，`doAction` 从 `ConfigUtil.getConfigValue("ztb", "mcertUrl")` 读手机证书服务器地址，用平台号初始化 `EpSignatureApi`（示例固定 `platformcode="A3205020001"`），匿名 `DefaultOutImpl.getPDF(Pdf)` 回调从 `pdf.getSrc()` 网络地址解析 attachGuid 取 PDF；`dealPDF()` 供服务器合并签章使用。
2. 新增 `com.epoint.EpointZBTool_BS.Signature.SignMobileAction.java`：`@RestController("signmobileaction") extends BasePage4BstoolNew`；`getParams()/GetPDFFilePath()` 提供待签章 PDF 网络路径；`initEpTools()` 提供统一社会信用码 + 合并签章 doaction 地址；`SetIsQianZhang()` 提供签章完成事件。pageLoad 接收 ShowType/Row_ID/AttachGuid；ShowType="QZ" 时 `initQZFileAttachGuid()` 取不到则跳转 WaringPage（"PDF文件未生成"）并返回 status=2。
3. 签章页面 `Sig_ZBPDFFile` 按系统参数 **`IsUseMobileCert`** 调整：=1 显示"签章方式选择"弹窗（**插入 CA 锁签章 / 手机扫码签章** 两种）；=0 默认 CA 签章。

## 三、OFD 阅读和签章（数科阅读器）

国产化环境用 **OFD 替代 PDF** 作版式文件格式；查看与签章控件用**数科阅读器**；Linux 客户端下 EpointCA 也需兼容。

**BSTool 改造**：新增系统参数——**版式文件类型**（可选 OFD/PDF，空默认 PDF）+ **OFD 打开方式**（目前为 2）。版式文件类型为空时签章控件按"PDF 打开方式"渲染；为 OFD 时按"OFD 打开方式"渲染。

**TPFrame（交易系统）改造**：
1. `BasePage`：`protected Boolean isuseOfd = "ofd".equalsIgnoreCase(getFrameConfigValue("版式文件类型"));`（不再写死）。
2. `YWPDFSignatureAction.initControl()`：
   ```java
   String strContentType = StringUtil.toUpperCase(getFrameConfigValue("版式文件类型"));
   ZtbDocType obj = new ZtbDocTypeDeal(strContentType).getDocType();
   documentType = obj.getDocumentType(); controlType = obj.getControlType(); registerKey = obj.getRegisterKey();
   if ("1".equals(getRequestParameter("isscansign")) && "pdf".equalsIgnoreCase(strContentType)) {
       controlType = getFrameConfigValue("mcertpdftype"); registerKey = getMcertRegisterKey();
   }
   ```
   配置为空抛出"请配置<版式文件类型>打开方式参数值"。
3. 前台 `YWPDFSignature.html`：初始 `var type='1'`（1=通过服务器上传，0=通过 iweboa 上传）、`var suffix=".pdf"`；OFD 模式判断：
   ```js
   if (EpointPDFControl1.SignCombineMode) { type = '0'; suffix = ".ofd"; }
   ```
   `DownLoadFile()` 将服务器文件下载到本地固定目录（`c:\iWebOA\<目录>\<guid() + suffix>`，已存在则复用）；**启用 OFD 模式时 `EpointPDFControl1.LockSignature()` 失效**，需处理为仅 `type=="1"`（PDF 模式）才调用。
4. `ZtbFileServerProxy` 类新增 OFD 转换方法，所有调用旧转 PDF 方法处替换。实例（`PDFPrint.java` Rev11433→11633）：`ConvertHtml2PdfAndSignOnServer(_Landscape)`、`ConvertHtml2PdfOnServer(_Landscape)` → **`ConvertHtml2OfdAndSignLandscape`、`ConvertHtml2OfdAndSign`、`ConvertHtmlLandscape`、`ConvertHtml`**（按 PrintDirection 选横版/竖版变体）。
5. **全局搜索 "application/pdf"**，联系上下文逐处判断（不能统一处理）是否改为/增加 "application/ofd"。SQL 示例：
   ```sql
   ... and (ContentType='application/pdf' or ContentType='application/ofd') ...
   ```
   （使 OFD 附件同样能被签章计数等逻辑查到。）

## 四、NTKO Office 替换 Office 组件

Windows 客户端**继续用软航控件**；Linux 客户端用**火狐 + WPS**。

1. `epointdocshowctl.js`：`ClientOS()` 通过 `navigator.platform` 检测（Win/Unix/Linux/Mac），结果写入控件 `data-options["clientOS"]` 传给后端。
2. 页面 `WebOffice.html`：
   - `SaveDoc`：先 `epoint.execute('token','@none',...)` 取 token，再拼到保存 URL：`...webOfficeUpAction.action?cmd=upload&DocContent...&token=<ret>`（WPS 无法操作 Cookie/会话，用 URL token 校验）；返回值 `"success" || true` 判成功。
   - `Change2PDF`：由本地 `ActiveXObject` 调 Word COM 改为 ajax：`epoint.execute("word2PDFAction.convert", null, [ClientGuid, FileCode, curAttachGuid], ...)`，服务端转换后 `obj.result=="y"` 则 `OpenPDF(obj.guid)`。
3. `webOfficeAction` 改造：
   - 新增 `token()` 方法：`return TokenUtils.createToken("TPBidder", 10);`
   - `getEpointdocshowValue(Map dataOptions)`：`"Linux".equalsIgnoreCase(dataOptions.get("clientOS"))` 时 `controlType` 由 "2"（Windows 控件）切 "3"（WPS/Linux 控件）；并内置 CanSignFile=true、DocumentType=Office 等。
4. `webOfficeUpAction` 改造：
   - 重写 `authorize(String cmd)`：配置免登录后有安全隐患，故未登录请求必须携带有效 token——`hasSession = StringUtil.isNotBlank(getSession().getUserGuid()); tokenValidate = StringUtil.isNotBlank(token) && TokenUtils.validateToken(token); if (!hasSession && !tokenValidate) return "token验签失败";`
   - `upload()` 兼容 WPS 取流：`officeType=="wps"` 时直接 `getReq().getInputStream()` + `getContentLength()`；否则按原 `FileItem("DocContent")` 表单方式。入库：新附件 `InsertToYeWuAttach(attachGuid, ".doc", ..., fileLength, is, clientGuid, ...)`（新增 fileLength 参数，md5 用 `GMd5Utils.MD5HashHex(is, GMd5Utils.getGUIDMD5Key())`）；已有 attachGuid 则 `updateAttachContent(is, attachGuid)`；最后 `sendResponse("success")`。
5. `EpointSSOClient.properties` 的 **`NoNeedAuthActions` 添上 `webOfficeUpAction`**。
6. `ywDocShowAction`、`hyDocShowAction` 同样处理。

## 六、达梦数据库迁移（MySQL→DM）

> MySQL 迁移达梦问题总结：EpointCommunity 帖子 TopicID=17923（OA 内网社区）。

实测踩坑五条：

1. **自定义函数与 DM 同名无法迁移**：如 Oracle 自定义函数 `DateDiff` 与 DM 内置 `datediff` 同名——解决：框架对 datediff 写法做兼容处理。
2. **Oracle→DM 时序列、触发器、存储过程不会被迁移**（含表字段自增列所依赖的触发器/序列），需手动处理。
3. **字段类型漂移**：迁移后部分字段 varchar 可能变 **clob**，遇到需手动处理。
4. **row_id 变主键**：框架表中 row_id 本不设自增也非主键，迁移后可能变主键，需注意处理。
5. **空字符串语义**：后台代码 `dataBean.setxxx('')` 塞值后，SQL 用 `xxx is null or xxx = 0` 查不到数据——需加 `xxx = ''`（DM 中空串与 null 不等价，行为与 MySQL 不同）。

## 七、国密算法改造

BSTool 涉及 Hash、3DES 等算法改国密，由产品部统一封装。新增系统参数 **`Bid_AlgorithmicTypes_BSTool`**，值 `xx:xx`：第一位 xx="SM" 表示启用国密；第二位为实现方式，默认 **`EPGM_0`**。

BSTool 加密点改造对照表（图片识别转录，9 处）：

| 加密场景 | 调用方法 | 现用算法 | 改造说明 |
|---|---|---|---|
| 导出范本对 zip 包加密 | `DigestUtils.md5Hex` | MD5 | 实际放入 xml 节点后没用到 |
| 招标公告服务器验签 | `ComFunction.HashString` | SHA1 | 不涉及与其他产品互动，直接改国密 |
| 生成招标文件 SoftVersion 加密 | `ComFunction.HashString` | SHA1 | 加参数决定是否启用国密；信封中加节点标记是否国密，供业务系统上传时判断 |
| 生成招标文件文件数字签名加密 | `ComFunction.HashString` | SHA1 | 同上 |
| 招标文件版本信息校验 | `ComFunction.HashString` | SHA1 | 根据信封新增节点判断是否国密，对应使用国密验证 |
| 招标文件签名信息校验 | `ComFunction.HashString` | SHA1 | 同上 |
| 会员登录 | `MDUtil.authPassword` | SHA1 | 通用解决方案 |
| 用户 id 登录 token 验证 | `TokenUtil.validateToken` | 3DES | 通用解决方案 |
| 生成招标文件数字签名加密 | `ComFunction.EncryptStr` | 3DES | 根据信封新增节点判断是否国密再对应验证 |

**关键机制**：不硬切算法——通过**信封 XML 新增节点**标记该文件是否国密加密，校验方按节点选择国密/国际算法验证，保证新旧文件兼容。

## 八、容器中间件使用 TongWeb

用 TongWeb 替换 Tomcat。TongWeb 有管理平台，**"应用管理 → 部署应用"→ 文件位置选"本机"→ 选择 war（如 BSTool.war）→ "开始部署"**。已部署列表可对应用做启动/停止/更新（重部署）/删除，支持 http/https 访问。实际环境部署示例：epane-content-server、convert-issuer、BSTool、ZTBFileWebServerJava（war / 文件部署 / 控制台部署）。

## 九、Ewebeditor 替换为百度编辑器

## 十二、DotZLib 解压

Java 与 .NET 的 zlib 流**前四个字节有区别**，改造后打通：修改 Java 支撑服务，替换原调用 .NET 支撑服务的代码为纯 Java 解压（`Server.java` 的 `/DotZLibDecompress` POST 接口，图片识别转录核心差异）：

```java
// 旧版：调用 .NET 支撑服务
// byte[] ret = Caller.CallProcessorSvr("DotZLibDecompress", null, dIns, os);

// 新版：纯 Java zlib 解压
dIns.skip(6);                                   // 跳过 .NET/Java zlib 头差异字节
InflaterInputStream inflaterInputStream = new InflaterInputStream(dIns);
final int size = 1024 * 1024 * 1000;
byte[] buf = new byte[size];
int count = 0;
while ((count = inflaterInputStream.read(buf, 0, count)) > 0) {
    os.write(buf, 0, count);
}
os.flush();
return getReturnValue(destfilePath);            // 解压输出 <FilePath>.xml
```

## 十三、龙芯 Docker 打包镜像

龙芯环境用 Docker 部署；因对打包服务器有要求，**不能用共用 Jenkins**，需走 **ecloud 流水线**打包镜像（流水线配置见基础设施文档：fdoc /rest/d/UZJrym）。

1. **SVN 初始密码**：流水线新增后用自动生成的 SVN 地址上传 war；初始密码在"共享交换平台 → 个人设置 → 修改登录密码"处查看（涉密不录入本文档）。
2. **构建镜像配置**：取消勾选"内置 Dockerfile"，把项目 Dockerfile 复制进配置内容，修改基础镜像（正文标注 registry.epoint.com.cn/base_mips64el/tongweb6:v0.7，持续更新；截图实例为 v0.3）：
   ```dockerfile
   FROM registry.epoint.com.cn/base_mips64el/tongweb6:v0.7
   MAINTAINER xxx <mail@epoint.com.cn>
   COPY App /usr/local/tomcat/webapps/BSTool
   ENV appbasepath /usr/local/tomcat
   LABEL appbasepath="/usr/local/tomcat" volumes="dockerize:/usr/local/bin/dockerize;" ...
   ```
   war 包内容解压缩至流水线 SVN 根路径即可（SVN 目录结构即 war 解包结构：WEB-INF、META-INF、frame、fui、js、pages 等）。
3. **TongWeb 配置外挂**：`/usr/local/tomcat/conf/tongweb.xml`，必须改 **8081、7200、8005、5100** 四个端口防冲突（可复制 `bstool_tongweb.xml` 修改）。
4. **端口规划**（每应用 4 端口错开）：

   | 应用 | 端口 |
   |---|---|
   | Nginx | 80 |
   | BSTool | 8081 7200 8005 5100 |
   | TPFrame | 8082 7201 8006 5101 |
   | TPBidder | 8083 7202 8007 5102 |
   | TPPingBiao | 8084 7203 8008 5103 |
   | convert-issuer | 8085 7204 8010 5104 |
   | ZtbFileWebServerJava | 8086 7205 8011 5105 |

5. **数科转换服务容器**需挂载目录：`Convert -> /usr/local/tomcat/webapps/convert-issuer/WEB-INF/Convert`。
6. **基础镜像为何是 debian**（基础设施部答复）：debian 只是基础镜像的 rootfs，用中标麒麟构建容器镜像也可以，但有三个问题——① 版权问题（用中标麒麟 OS 构建其容器镜像涉及版权）；② 中标麒麟的 **mips 版本在 X86 下做混合 docker build 存在问题**，debian 可以，为节省一台构建机与编译时间，mips 基础镜像定为 debian；③ 项目上若确定用中标麒麟系统，可提供中标麒麟容器（无混合编译即无兼容性问题），但同样需获得中标麒麟授权。

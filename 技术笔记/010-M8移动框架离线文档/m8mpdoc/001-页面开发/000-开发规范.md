# 开发规范

为了实现多端兼容，综合考虑编译速度、运行性能等因素，`M8跨端框架` 约定了如下开发规范：

-   页面文件遵循 [Vue 单文件组件 (SFC) 规范](https://vue-loader.vuejs.org/zh/spec.html)
-   组件标签靠近微信小程序规范，详见以下介绍。
-   数据绑定及事件处理同 `Vue.js` 规范，同时补充了页面的生命周期，具体可查看[生命周期](/m8mpdoc/index.html?file=001-%E9%A1%B5%E9%9D%A2%E5%BC%80%E5%8F%91/009-%E7%94%9F%E5%91%BD%E5%91%A8%E6%9C%9F)的介绍。
-   为兼容多端运行，建议使用 flex 布局进行开发
-   跨端框架所有页面默认会在模板的第一层节点内部添加`ejs`的UI模块节点，所以页面模板的第一层节点尽量使用`view`或者`div`标签，请不要使用自定义组件作为第一层节点

## 组件规范

### 组件的属性类型

组件的属性，有多种类型：

| 类型         | 描述           | 注解                                                                                                                                                     |
| :----------- | :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Boolean      | 布尔值         | 组件写上该属性，不管该属性等于什么，其值都为 `true`，只有组件上没有写该属性时，属性值才为 `false`。如果属性值为变量，变量的值会被转换为 `Boolean` 类型。 |
| Number       | 数字           | 1, 2.5                                                                                                                                                   |
| String       | 字符串         | "string"                                                                                                                                                 |
| Array        | 数组           | [ 1, "string" ]                                                                                                                                          |
| Object       | 对象           | { key: value }                                                                                                                                           |
| EventHandler | 事件处理函数名 | `handlerName` 是 methods 中定义的事件处理函数名                                                                                                          |
| Any          | 任意属性       | &nbsp;                                                                                                                                                   |

下面的例子演示了组件的属性设置 boolean 值和数字的例子。注意`false`作为一个 js 变量，在组件的属性中使用时，属性前面需增加`:`冒号前缀，属性值仍使用引号包裹，但引号里不是字符串，而是 js。

```html
<template>
    <view>
        <button size="mini" :disabled="false" hover-start-time="20">按钮</button>
    </view>
</template>
```

### 公共属性列表

每个组件都有各自定义的属性，但所有 框架 的内置组件，都有如下属性：

| 属性名  | 类型         | 描述                 | 注解                                                                              |
| :------ | :----------- | :------------------- | :-------------------------------------------------------------------------------- |
| id      | String       | 组件的唯一标示       | 一般用于获取组件上下文对象，需要保持整个页面唯一                                  |
| ref     | String       | vue 中组件的唯一标示 | 用来给子组件注册引用信息                                                          |
| class   | String       | 组件的样式类         | 在对应的 css 中定义的样式类                                                       |
| style   | String       | 组件的内联样式       | 可以动态设置的内联样式                                                            |
| hidden  | Boolean      | 组件是否隐藏         | 所有组件默认是显示的                                                              |
| data-\* | Any          | 自定义属性           | 组件上触发的事件时，会发送给事件处理函数                                          |
| @\*     | EventHandler | 组件的事件           | 详见各组件详细文档，事件绑定参考 [事件处理器](/tutorial/vue-basics?id=事件处理器) |

除了上述公共属性，还有一类特殊属性以`v-`开头，称之为 vue 指令，如 v-if、v-else、v-for、v-model等。

### 内置组件

M8 跨端框架的组件，分为内置组件和参考 vant 规范开发的跨端组件。

内置组件在框架中已经内置，无需将内置组件的文件导入项目，也无需注册内置组件，随时可以直接使用，比如`<view>`组件。

除了框架提供的内置组件和封装的跨端组件，其他组件需要将组件导入项目中才可以使用。

框架为开发者提供了一系列内置组件，类似 HTML 里的基础标签元素。

但 框架 的内置组件与 HTML 不同，而是与平台小程序相同，可更好的满足手机端的使用习惯。

虽然不推荐使用 HTML 标签，但实际上如果开发者写了`div`等标签，在编译到非 H5 平台时也会被编译器转换为`view`标签，类似的还有`span`转`text`、`a`转`navigator`等，包括 css 里的元素选择器也会转。但为了管理方便、策略统一，新写代码时仍然建议使用 view 等组件。

开发者可以通过组合这些基础组件进行快速开发。在需要复用的情况下可封装成自定义组件。

框架的内置组件规范，与平台小程序规范相近。如果了解微信小程序开发的话，对内置组件会感觉很熟悉。但需要注意组件上的事件绑定，需要以 vue 的事件绑定语法来绑定，如 bindchange="eventName" 事件，需要写成 `@change="eventName"`

```html
<picker mode="date" :value="date" start="2015-09-01" end="2020-09-01" @change="bindDateChange">
    <view class="picker">当前选择: {{date}}</view>
</picker>
```

### 组件的类别

框架支持的组件分为 vue 组件和平台小程序自定义组件。

如果你还不了解这两种组件，可以参阅各自的文档

-   vue 组件：[文档](https://uniapp.dcloud.net.cn/tutorial/vue-components?id=%e6%a6%82%e5%bf%b5)
-   平台小程序自定义组件：其规范不是 vue 规范，而是平台小程序规范，[文档](https://uniapp.dcloud.net.cn/tutorial/miniprogram-subject.html#小程序自定义组件支持)

日常开发来讲，推荐使用 vue 组件。框架支持平台小程序组件主要是为了兼容更多生态资源。

如果自定义组件符合 框架 的`easycom`组件规范，则可以免注册，直接使用。`easycom`相关[详见](/m8mpdoc/index.html?file=0001-前期准备/005-pages)

如果组件不符合 easycom 规范，则需要在代码里手动 import 和注册组件，然后才能使用。

### 平台小程序原生组件

#### 平台小程序原生组件说明

平台小程序的 vue 页面，主体是 webview 渲染的。为了提升性能，平台小程序的 vue 页面下部分 ui 元素，比如导航栏、tabbar、video、map 使用了原生控件。这种方式被称为混合渲染。

虽然提升了性能，但平台小程序原生组件带来了其他问题：

1. 前端组件无法覆盖原生控件的层级问题
2. 平台小程序原生组件不能嵌入特殊前端组件(如 scroll-view)
3. 原生控件 ui 无法灵活自定义
4. 原生控件在 Android 上，字体会渲染为 rom 的主题字体，而 webview 如果不经过单独改造不会使用 rom 主题字体

H5端和新点小程序端的页面，不存在混合渲染的情况，它们或者全部是前端渲染、或者全部是原生渲染，不涉及层级问题。

#### 混合渲染模式下平台小程序原生组件的使用限制

由于平台小程序原生组件脱离在 WebView 渲染流程外，因此在使用时有以下限制：

-   平台小程序原生组件的层级是**最高**的，所以页面中的其他组件无论设置 z-index 为多少，都无法盖在原生组件上。后插入的平台小程序原生组件可以覆盖之前的平台小程序原生组件。
-   平台小程序原生组件无法在 scroll-view、swiper、picker-view、movable-view 中使用。
-   同层渲染支持：微信基础库 2.4.4 起支持了 video 的同层渲染、微信基础库 2.8.3 支持 map 的同层渲染。支持同层渲染后，相关组件的时候不再有层级问题，无需再使用 cover-view 覆盖，也可以内嵌入 swiper 等组件。
-   需要注意的是，微信原生组件的「同层渲染」能力可能会在特定情况下失效，一方面你需要在开发时稍加注意，另一方面同层渲染失败会触发 `bindrendererror` 事件，可在必要时根据该回调做好 UI 的回退。

可在组件中监听同层失败回调 bindrendererror 来判断

-   部分 CSS 样式无法应用于平台小程序原生组件，例如：
    -   无法对平台小程序原生组件设置 CSS 动画；
    -   无法定义平台小程序原生组件为 position: fixed；
    -   不能在父级节点使用 overflow: hidden 来裁剪平台小程序原生组件的显示区域。
-   在平台小程序端真机上，平台小程序原生组件会遮挡 vConsole 弹出的调试面板。

#### 内置组件里的平台小程序原生组件

框架的内置组件里，有一批平台小程序原生组件，如 video、map...

这些组件如果用于 vue 页面，也就是 webview 渲染时，会造成层级高于普通前端组件的情况。

它们的层级需要使用 cover-view 等特殊组件才能覆盖。

框架中平台小程序原生组件清单如下：

-   [map](/m8mpdoc/index.html?file=017-内置组件/018-map)
-   [video](/m8mpdoc/index.html?file=017-内置组件/010-video)
-   [camera](/m8mpdoc/index.html?file=017-内置组件/008-camera)（仅微信小程序支持）
-   [canvas](/m8mpdoc/index.html?file=017-内置组件/013-canvas)（仅在微信小程序表现为微信小程序原生组件）
-   [input](/m8mpdoc/index.html?file=017-内置组件/019-input "input")（仅在微信小程序、支付宝小程序中且 input 置焦时表现为平台小程序原生组件，其中支付宝小程序的 input 仅为 text 且置焦时才表现为平台小程序原生组件）
-   [textarea](/m8mpdoc/index.html?file=017-内置组件/020-textarea)（仅在微信小程序表现为微信原生组件）
-   [live-player](/m8mpdoc/index.html?file=017-内置组件/011-live-player)（仅微信小程序直接使用 video 组件可同时实现拉流）
-   [live-pusher](/m8mpdoc/index.html?file=017-内置组件/012-live-pusher)（仅微信小程序支持）
-   [cover-view](/m8mpdoc/index.html?file=017-内置组件/005-cover-view)
-   [cover-image](/m8mpdoc/index.html?file=017-内置组件/006-cover-image)

#### 其他原生界面元素

除了平台小程序原生组件外，框架在非 H5 端还有其他原生界面元素，清单如下：

-   原生 navigationBar 和 tabbar（pages.json 里配置的）。
-   web-view 组件虽然不是原生的，但这个组件相当于一个原生 webview 覆盖在页面上，并且平台小程序上 web-view 组件是强制全屏的，无法在上面覆盖前端元素
-   弹出框：chooseImage、chooseVideo 等弹出元素也无法被前端组件覆盖

#### vue 页面层级覆盖解决方案

为了解决 webview 渲染中平台小程序原生组件层级最高的限制，框架提供了 `cover-view` 和 `cover-image` 组件，让其覆盖在平台小程序原生组件上。

`cover-view`只能覆盖平台小程序原生组件，不能覆盖其他原生界面元素。比如 cover-view 可以覆盖 video、map，但无法覆盖原生导航栏、tabbar、web-view。

微信小程序在基础库 2.4.0 起已支持 video 组件的同层渲染，2.7.0 起支持 map 组件的同层渲染。可以被前端元素通过调节 zindex 来遮挡，也支持在 scroll-view 等组件中内嵌这 2 个平台小程序原生组件。但 video 全屏时，仍需要 cover-view 覆盖。

如果你的层级覆盖问题比较简单，不用嵌套，且有跨端需求，就使用 cover-view。

# 招标范本结构化切分

把一份招标文件范本（Word）切成招标工具能导入的结构化素材。按“默认直接出结果，拿不准才提示”的方式工作。

本文件的规则来自四套已切好的范本，以及范本维护工具“招标菜单”“投标菜单”“扫描件”页面的枚举：

| 资料包 | 特点 |
|---|---|
| 佛山通用3.0 | 已批注，覆盖多种招标类型，字段代码齐全，勾选删除型 |
| 广西检测2026 | 原始范本，旧包按2020旧版做，公告取业务公告 |
| 湖南工程总承包2024 | 原始范本，包与范本完全一致，勾选保留型 |
| 广东智能辅助评标1.09 | 广州GZZB2018-3通用条款，包与范本基本一致；不埋任何条件标记，评标办法整章保留原文，标书类别填得最全 |

各包差异很大的地方都标明了“按资料包”。

所有枚举列在输出里一律写工具下拉里的中文名称，不写代码；代码只在读旧包时用来还原中文名称。

## 一、范围

招标文件 ＝ 切出来的素材 ＋ 系统生成或设置的评标办法。

- 要切：评标办法以外的全部内容，分代理端和投标人端两个角色。
- 评标办法：默认只在前附表、评分细则位置留“内容替换标记”，不切内容。也有资料包把评标办法整章当固定文字保留在正文里（广东），按资料包。
- 不管：评审流程、活动、评分点配置。包里的 PingBiao_Eval_* 表和 BaseFormula.xml 属于评标办法开发，不读也不输出。
- 输出到切分清单、埋点清单、带标记文字的Word底稿、html及其Word版本为止。不生成系统包，由用户的人导入。
- 条件标记的触发逻辑写在程序里。这里只负责埋点、命名、写明触发含义。

输出与范本维护工具左侧菜单的对应：

| 工具菜单 | 对应的输出 |
|---|---|
| 原始正文 | 带标记文字的Word底稿 |
| 招标菜单 | 招标菜单表（第五节） |
| 投标菜单 | 投标菜单表＋html和Word（第六节） |
| 扫描件 | 扫描件表（第六节第6小节） |
| 一览表 | 开标一览表字段 |

## 二、输入与场景

1. 待切分的范本（.doc 或 .docx）。范本里的批注和写在空格处的字段代码是最重要的信号，必须读。
2. 参考资料包（切分字典工作簿、html模板库、Word版本）。资料包按“平台＋地区”区分，选与目标系统相同的那一套。用户没上传时先向用户要；确实没有，就按本文件内置规则做，并在结果开头说明“未使用字典”。
3. 可选：同一范本旧版的结构化包（系统导出的zip）。

先判断场景，在结果开头写明：

| 场景 | 特征 | 主要依据 |
|---|---|---|
| A 已批注范本 | 范本里有业务批注，或空格处写着字段代码 | 批注和代码 |
| B 原始范本 | 没有批注、没有代码 | 第四、五节规则＋字典，输出带置信度的候选清单 |
| C 换版 | 有旧版结构化包 | 旧包的埋点，只对变化部分重新判断（见第十二节） |

A和C可以同时成立。场景B要在结果里说明准确率有限，并建议业务先在范本上批注，或提供旧包。旧包里的范本原文与待切范本基本一致时（湖南完全一致；广东只差一段旧公告和章号），说明已经切过，直接做读包自检并告诉用户。

## 三、流程

1. 读范本：转成docx，按文档顺序取出正文、批注及批注所标位置、正文里的代码、下划线、表格单元格。
2. 读参考资料包；有旧包时读旧包并做读包自检。
3. 划分章节，生成招标菜单表。
4. 代理端：对显示方式为“HTML页面”的模块逐段识别控件、条件、替换、结构标记，生成埋点清单和Word底稿。
5. 投标人端：从“投标文件格式”一章切出节点，生成投标菜单表、html和Word版本；再根据投标文件要求的证明材料选出扫描件。
6. 汇总字段字典，标出新增项。
7. 自检。
8. 输出工作簿、底稿、html；回复里先列需确认清单，最后附“导入前必做事项”。

材料读完之前不要开始写输出。范本很长，分章处理，不要整本一次判断。

## 四、读取范本

.doc 先用 `soffice --headless --convert-to docx` 转换。要看纯文本时用 `--convert-to 'txt:Text (encoded):UTF8'`，否则中文和标记会变成问号。转成纯文本会丢批注和下划线，判断空位必须解析docx。

批注有两种挂法，都要取：成对的 `commentRangeStart/End`，和只有一个点的 `commentReference`。只取前一种会漏掉大部分批注。没有 `word/comments.xml` 就是无批注。

```python
import re, zipfile
z = zipfile.ZipFile(path)
x = z.read('word/document.xml').decode('utf-8')
c = z.read('word/comments.xml').decode('utf-8') if 'word/comments.xml' in z.namelist() else ''
comments = {m.group(1): ''.join(re.findall(r'<w:t(?:\s[^>]*)?>([^<]*)</w:t>', m.group(2)))
            for m in re.finditer(r'<w:comment [^>]*w:id="(\d+)"[^>]*>(.*?)</w:comment>', c, re.S)}
text, start, end = '', {}, {}
pat = (r'<w:commentRangeStart w:id="(\d+)"/>|<w:commentRangeEnd w:id="(\d+)"/>|'
       r'<w:commentReference w:id="(\d+)"/>|<w:t(?:\s[^>]*)?>([^<]*)</w:t>|(</w:p>)|(</w:tc>)')
for m in re.finditer(pat, x):
    if m.group(1): start[m.group(1)] = len(text)
    elif m.group(2): end[m.group(2)] = len(text)
    elif m.group(3): start.setdefault(m.group(3), len(text)); end.setdefault(m.group(3), len(text))
    elif m.group(4) is not None: text += m.group(4)
    else: text += '\n'
```

每条批注记录：所在章节、条款号（向前找最近的 1.4.2 这类编号）、所标文字、前文。场景B还要记录每个字符是否带下划线（run里的 `<w:u w:val=...>`）和是否位于表格单元格。符号字体的方框（转成文本后常显示为“£”）等同于“□”。

### 批注和正文写法对应的动作

| 范本里的写法 | 动作 |
|---|---|
| 空格处或批注里是一串代码 | 该处是控件，代码即字段代码 |
| “□代码文字”，代码以0、1结尾 | 复选框；同组选项互斥 |
| 自动获取、自动带出、从BS获取、反填 | 系统带出字段 |
| 投标文件格式里的“@自动获取” | 主体库绑定字段 |
| “#编辑框，填写” | 手填字段 |
| 只显示勾选的、二选一、N选一展示选择的 | 勾选删除型：每个选项各包一对条件标记 |
| XX显示、含XX时显示、根据招标类型显隐 | 该段包一对条件标记，按适用对象命名 |
| 评标办法显示、根据评标办法显隐 | 该段包一对条件标记，按评标办法命名 |
| html格式、由word改成html | 节点形态为html |
| word格式 | 节点形态为Word |
| 日期格式YYYY年MM月DD日 | 日期控件 |
| 默认打勾、默认值为…… | 记录默认值 |
| 需推送给评标、推送出来 | 字段供评标使用，备注“代码不得改名” |
| 这不是正文只是说明、导入时删除 | 不进正文，不埋点，在需确认清单里注明已忽略 |
| 写死 | 固定文字，不做控件 |
| 不给填，留着盖电子章 | 留空，不做控件 |

### 场景B：没有批注时怎么识别空位

按置信度分档，不要全部当成确定结果。湖南、广东两个包与范本一致，是校准样本。括号里第一个数是湖南投标人须知的字符级精度，第二个是广东投标须知的行级精度：

| 置信度 | 信号 | 动作 |
|---|---|---|
| 高 | “□”及符号字体方框；下划线（93%／100%）；“年 月 日（时 分）”一组（100%／100%）；空格夹着的提示语，如“ 电子招标投标交易平台名称 ”（100%，提示语整体换成文本框）；前附表里紧跟标签的空单元格（100%／100%） | 直接埋点 |
| 中 | 句中三个以上连续空格（78%／88%）；行尾空格（75%／91%）；以冒号结尾的短行（59%／71%）；“③………”这类可续写的省略号；括号提示语如“（招标项目名称）”；前附表里招标人可改的预填文字（如“当地交易中心”，做成文本框并把原文作默认值） | 埋点，标“中”，列入需确认清单 |
| 不算 | 行首缩进空格；“如下：”“要求：”“包括：”等引导行；表格里用于排版的空单元格；修改表里的“条款号　修改类型”“原文：”“现文：”（广东的误报全部来自这里） | 不埋点 |

以上合计召回：湖南约89%，广东96%。广西范本用同样的信号精度只有30%～45%，原因不是识别不准，而是该包对很多空位故意不埋点。哪些空位要埋是口径问题，不是识别问题：

- 招标公告的显示方式是“获取业务公告”的平台（广西、佛山），项目名称、投标截止时间、开标时间等已在公告里录入，前附表里对应空位不埋或改为系统带出。
- 招标公告是“HTML页面”的平台（湖南、广东），这些空位照常埋文本框。
- 范本写“详见招标公告”的位置不埋。

## 五、代理端切分

### 1. 招标菜单：用系统枚举

每个章节或功能对应招标菜单里的一个模块。每个模块要给出四项：模块名称、显示方式、模块类型、排序。显示方式和模块类型只能取下面的枚举值，原样书写，不要用自己的叫法。

**模块名称**跟随范本章名（去掉章号），如广东用“投标须知”“投标人所需其他材料”“工程量清单”，湖南、广西用“投标人须知”。功能页的名称按资料包，如“评标办法”或“评标办法设置”。

**显示方式**（括号内是包里对应的页面地址）：

| 枚举值 | 含义 | 页面地址 | 典型模块 |
|---|---|---|---|
| HTML页面 | 结构化表单：正文固定，只填空和勾选，需要埋点 | RedirectByRQ.aspx | 封面、否决性条款摘要、投标无效中标无效的认定及处理、致投标人、投标人声明（广东）、投标人须知；湖南、广东的招标公告 |
| Word导入 | 由招标人导入或编辑整篇Word，不埋点 | DocCanEdit.aspx | 合同条款及格式、技术标准和要求、发包人要求、发包人提供的资料、用户需求书、图纸、投标人所需其他材料（广东）、工程量清单（非固化） |
| 获取业务公告 | 从业务系统取已发布的公告 | PriewGongGao.aspx | 佛山、广西的招标公告/投标邀请书 |
| 标准版地址 | 系统标准功能页 | DaYi_List、Frame_CanShuSZ、TBFileNodes、UPR_ZBOtherFile、ShengChengZBFile、UploadQingDan、UploadCAD 等 | 答疑说明文件导入、评标办法（设置）、投标文件格式、招标文件的其他材料、生成招标文件、生成答疑文件、工程量清单（固化）上传、图纸上传 |
| 个性化地址 | 平台定制的功能页 | 非标准页面，如 KBInfo/KBInfoSet.aspx | 开标一览表 |

判定顺序：能对应到系统功能的，按资料包里同名模块的显示方式；其余章节正文固定只填空的用“HTML页面”，整篇由招标人提供的用“Word导入”。招标公告在“HTML页面”和“获取业务公告”之间按资料包定，没有资料包时列入需确认清单。“个性化地址”只在资料包里同名模块就是它时使用。

“Word导入”模块在包里各带一份Word，初始内容就是范本该章的正文（多数只有一句“注：本章由招标人自行制定。”）。输出时把这段原文写进招标菜单表的“初始内容”列。

**模块类型**（括号内是包里的代码）：

| 枚举值 | 用在 |
|---|---|
| 招标文件（ZB） | 只在编制招标文件时显示的模块，如“生成招标文件” |
| 答疑文件（DY） | 只在编制答疑文件时显示的模块，如“答疑说明文件导入”“生成答疑文件” |
| 招标和答疑（ZB&DY） | 其余正文模块和功能页，默认值 |
| 控制价、清单文件 | 控制价、清单单独编制发布的模块 |
| 资审文件、资审澄清文件、资审和资审澄清 | 资格预审文件范本里的模块，分别对应招标文件、答疑文件、招标和答疑 |

**排序**：数字越大越靠前。四个包的惯例：答疑说明文件导入 200；封面 180；投标人声明等封面后的页 170；招标公告 160；投标人须知 140；评标办法 120～130；合同条款 100～120；其余章节按范本顺序递减（工程量清单 100、图纸 90、技术标准 80）；投标人所需其他材料 50～70；投标文件格式 60～70；生成招标文件 20～50；生成答疑文件最后。插入新模块时在相邻两值之间取值，不重排已有模块。

**固定模块**：即使范本里没有对应章节，也要列出：
- 答疑说明文件导入（标准版地址、答疑文件）
- 评标办法设置（标准版地址、招标和答疑）
- 投标文件格式或投标文件组成设置（标准版地址、招标和答疑）
- 生成招标文件（标准版地址、招标文件）
- 生成答疑文件（标准版地址、答疑文件）

是否要“招标文件的其他材料”“开标一览表”按资料包。

### 2. 标记

只有显示方式为“HTML页面”的模块需要在正文里埋点。“Word导入”和各类功能页只在正文里留一个内容替换标记，或者按资料包不留（见第4小节）。

底稿里的标记文字用这套写法，括号内是标记名称：

```
<--分页标记(名称)-->
<--内容选取开始标记(名称)-->  ……  <--内容选取结束标记(名称)-->
<--内容条件选择开始标记(名称)-->  ……  <--内容条件选择结束标记(名称)-->
<--内容替换标记(名称)-->
```

占位文字：
- 文本框写“文本”，复选框保留“□”，日期控件写“日期”。
- 单选列表写“选择”，下拉框写下拉的含义（如“时”）。
- 引用系统数据的控件写字段名，如“招标人”“招标代理”“项目名称”“标段名称”。

| 标记 | 何时用 |
|---|---|
| 文本框 | 空位。内容较长或可多行的标“多行” |
| 复选框 | 范本里的“□”及符号字体方框；以及下面“版本二选一”补加的勾选 |
| 单选列表 | 一组互斥“□”且选完后其余文字不用删（如“□不允许 □允许：……”）。整组换成一个单选控件，选项用分号分隔，如“不允许;允许”。按资料包，广东用，其他包用复选框 |
| 日期 | 发布日期、落款日期等只填日期的空位 |
| 下拉框 | 选项固定的短值，如小时“00;01;…;23” |
| 内容条件选择 | 某段文字只在特定条件下保留 |
| 内容替换 | 该位置由系统生成内容或由Word导入模块的内容填入 |
| 内容选取 | 一个“HTML页面”模块的起止。名称必须与模块名称一致（包里就是该模块的 WordTag）；同一模块被分页切成多段时，每段各一对，名称相同 |
| 分页 | 每个“HTML页面”模块开头一个；投标人须知在前附表、修改表和每个一级标题（总则、招标文件、投标文件、投标、开标、评标、合同授予……）各一个；招标公告、投标邀请书、评标办法的各部分也各一个。名称用标题 |

“年 月 日 时 分”一组的处理按资料包：
- 湖南：整组合成一个文本框。
- 广东：“年 月 日”做日期控件，“时”做下拉框（00～23）。
- 没有资料包时合成一个文本框。

分页切出的段之间、模块之外的文字（目录、章标题）不进内容选取。

### 3. 条件标记与勾选

三类条件：

| 类别 | 何时埋 | 命名 |
|---|---|---|
| 选项勾选 | 一组互斥选项，每个选项连同它带出的内容各包一对（仅勾选删除型） | 事项＋选项，如“联合体投标接受” |
| 招标类型 | 段落只适用于某类或某几类招标 | 适用对象＋事项，如“房建市政监理水利监理资质” |
| 章级或部分级多选一 | 招标公告、投标邀请书、资格预审通过通知书；多种评标办法各占一章；技术方案暗标与明标 | 章名或部分名，如“招标公告”“技术方案暗标” |

选项的三种风格，按批注或资料包决定：

| 风格 | 做法 | 见于 |
|---|---|---|
| 勾选删除型 | 每个选项各包一对条件标记，生成时只保留勾选的 | 佛山3.0（批注写“只显示勾选的”） |
| 勾选保留型 | 选项只做复选框或单选列表，生成时显示☑/□，不包条件标记 | 广西、湖南 |
| 全保留型 | 不埋任何条件标记。“（选择性条款）”、“方式一/方式二”、多种可选评标办法都原样留在正文里，由招标人在修改表或前附表里说明取舍 | 广东（范本自带投标须知修改表、评标办法修改表） |

没有批注时：
- 范本带“修改表”且用“（选择性条款）”标注可选内容的，按全保留型。
- 其余默认勾选保留型，只对章级或部分级多选一、招标类型包条件标记。
- 两种情况都要在需确认清单里问一次风格。

版本二选一补加勾选（按资料包，湖南做，广东不做）：范本对同一条款给了几种写法（如“4.2.1未进行资格预审的……”和“4.2.1已进行资格预审的……”），或一项内容列了几个“（适用于……）”的备选项但没有方框时，在每种写法前加一个复选框。湖南包比范本多出的复选框都是这一类。

命名规则：
- 名称只用汉字，不带标点。
- 同一条件用在多处，名称后加“一、二、三……”区分，保证全文不重名。
- 开始和结束标记的名称必须完全相同。
- 条件可以嵌套，嵌套时内层完整落在外层之内。
- 每条写明触发含义，用开发能直接实现的说法，如“1.4.2选‘接受’时保留”“招标方式为邀请招标时保留”“技术方案采用暗标时保留”。

### 4. 内容替换与原文保留

以下位置放替换标记，不切内容：
- 评标办法前附表（及其承前页）、入围方式、定标因素表。
- 各招标类型的评分细则。范本覆盖多种招标类型时，每种评标办法下每种招标类型一组：外包一对招标类型条件标记，内放一个替换标记，名称如“施工评分细则二”。
- 显示方式为“获取业务公告”的招标公告或投标邀请书。各自外包一对章级条件标记。
- 投标文件格式一章，名称固定用“投标组成”（湖南、广东一致）。
- 技术方案格式分暗标、明标时，各一个替换标记，外包对应条件标记。
- 显示方式为“Word导入”的各模块。

替换标记的名称用范本里的章名或部分名，不带章号。它不要求与招标菜单的模块名称一致，各包里都有不一致的情况（湖南“评标办法前附表”，广东“技术标准与要求”对应模块“技术标准和要求”）。导入时由人在工具里关联，所以清单里要写明每个替换标记对应哪个模块。

原文保留（按资料包）：广东包把下列章节的范本原文直接留在正文里，不放替换标记，也不进内容选取：
- 第三章评标办法整章，包括修改表、通用条款、8种可选办法、附表。菜单上另有“评标办法”参数设置页。
- 第五章工程量清单的附件。菜单上另有清单上传页。
- 第六章技术条件。没有对应模块。

没有资料包时，评标办法按替换标记处理；没有对应模块、只有一句说明的章节按原文保留，并列入需确认清单。

### 5. 可增删条款的列表

招标人可以整体增删改的条款列表（如否决性条款的各项情形），整段做成一个多行文本框，不逐条埋点。默认文字存放在哪里需要用户确认，列入需确认清单。

### 6. 字段代码

字段代码不是每个控件都必须有：
- 佛山345个控件几乎都有代码。
- 广西89个、湖南329个、广东161个全部没有代码。
- 引用系统数据的控件在定义里写 `sysTableName="引用Y"`、`sysFieldName="招标人"`，只读。

先判断要不要起名：
- 必须起名：系统引用的字段（招标人、招标代理、项目名称、标段名称等）；多处反填的同一参数；推送评标或开标的字段。
- 可不起名：只在一处出现、只供生成正文的普通空位。资料包里同类控件没有代码的就不起。

要起名时：
1. 范本里写明了代码的，直接用。
2. 没写明的，按“章节＋条款号＋前文”查控件字典，对上的沿用。
3. 都没有的新增，标注“新增”。命名风格跟随资料包：佛山用英文或拼音缩写（互斥选项同一词干加0、1、2）；广西用中文名加序号（如“投标有效期1/2/3”）。
4. 同一参数出现在多处，用同一个代码，系统会反填。
5. 备注“需推送给评标”的代码不得改名。

## 六、投标人端切分（投标菜单、扫描件）

来源是范本的“投标文件格式”一章。输出两张与工具页面同列的表：投标菜单、扫描件。

### 1. 节点树（文件结构）

- **第一层**：范本的每一节或每一部分是一个分类。
  - 例子：资格审查、技术标、商务标、经济标、定标资料；湖南为投标函、投标报价、技术方案暗标、技术方案明标；广东为投标函格式、投标报价格式、施工组织设计格式（明标）。
  - 暗标和明标各自成一个分类，都设为非必须，由招标人的暗标设置决定用哪个。
- **每个分类下**：一个封面节点，然后该部分目录里的每一项各一个节点。
- **一个目录项下有多张表或多种格式**：目录项作“网上资料挑选类型-标题”节点，每张表作“网上资料挑选类型-子节点”（广东的“项目管理机构”“资格审查资料”即如此）。
- **目录项下只有一张主体库表**：也建“标题＋子节点”两层。
- **末尾**：加一个“其他材料”节点。广东把它放在第一层，与各分类并列。

文件结构编号：分类用1、2、3；节点用两位小数，如1.02；子节点再加两位，如1.02.01。同级连续，不重复。

### 3. html还是Word

html化的程度各平台差别很大：

| 资料包 | html节点 | 说明 |
|---|---|---|
| 佛山 | 50个内容节点中33个 | |
| 广西 | 22个中8个 | |
| 湖南 | 30个中4个 | 三个封面和投标函 |

湖南、广东其余节点全是Word，且不绑定主体库。所以按以下顺序判断：
1. 批注写明的照办。
2. 其次看资料包里同名或同类节点的形态。
3. 都没有时，投标函（及单独的报价函）用html，其余用Word，并把“固定表格且数据来自主体库”的节点列为“建议html”，写进需确认清单。

资料包倾向html时，默认规则如下：

| 情况 | 形态 |
|---|---|
| 封面 | 按资料包（佛山、湖南、广东为html，广西为Word） |
| 固定表格，数据来自主体库 | html |
| 固定承诺或声明文本，只填空 | html |
| 固定版式的填报表 | html |
| 投标函及投标函附录 | 投标函html；附录按资料包 |
| 自由文本（方案、大纲、说明、技术标正文） | Word |
| 协议样式、第三方出具的文件 | Word |
| 有多个模板或行数不定、无法固化 | Word |
| 以扫描件为主的资料 | Word |

形态决定显示方式：独立的html节点用“Html显示”，独立的Word节点用“直接导入word”，子节点不论形态都用“网上资料挑选类型-子节点”。

结果里每个节点注明依据是“批注”“资料包”还是“默认规则”。每个html单元都要同时出一份Word版本。

### 4. 复用

同一张表用在多处时，html基本相同，只改数据筛选的类型值和标题。先在模板库里找同类单元，在它的基础上改。同表在不同部分重复出现时，节点名加后缀区分，如“检测项目负责人简历表（资）”。

### 5. 按功能认节点，不按名称

技术标正文不一定叫“技术标正文”：广西叫“工程检测大纲”，湖南叫“技术方案（暗标）/（明标）”，广东叫“施工组织设计”。判断依据是它承担自由编写的技术正文。

投标函同理。投标报价单独成函（广东“报价函”）时，带报价、开标唱标的那封函才是文件类型“投标函”。

文件类型按功能定，不要照抄相邻行。发现以下情况时，在需确认清单里提示：
- 带报价的函的文件类型不是“投标函”。
- 普通节点被设成“技术标（施工组织设计）”之类。

## 八、什么时候停下来提示

以下情况不要自行决定，列入需确认清单；能给默认处理的先按默认做，并写明做了什么：

- 范本里出现模板库和字典里都没有的单元或表格。
- 招标菜单里无法判定显示方式或模块类型的模块；用到“个性化地址”或后五种模块类型的模块。
- 评标办法章按替换标记处理还是原文保留；没有对应模块的章节按原文保留。
- 投标菜单：用到“保函、业绩资料……”等未用过的文件类型；读包时非技术节点被设成“技术标（施工组织设计）”；“投标”一列怎么填；智能辅助评标范本的标书类别。
- 扫描件：是否需要扫描件；个性化添加的项；与目录同代码不同名的项；归属推定的大类。
- html和Word都说得通，且没有批注、资料包里也没有同类。
- 字段在字典里找不到，或同名但含义不同。
- “（如有）”的节点找不到明确的触发条件。
- 批注之间、批注和正文之间矛盾。
- 批注写了“删除”“暂不更新”等，无法判断是否进正文。
- 条件范围不清，无法确定开始或结束位置。
- 可增删条款列表的默认文字来源。
- 场景B里置信度为“中”的空位；选项用哪种风格（勾选删除、勾选保留、全保留）；互斥□用复选框还是单选列表。
- 读包自检发现的旧包问题。

只有一种情况要在开始前先问：范本的招标类型和评标办法范围无法从范本判断，且会影响整体结构。其余都先做完再集中提示。

### 3. 对比与沿用

1. 新范本与旧包里的范本原文按章节和条款号对齐，逐段比对。注意旧包可能基于更早的版本：广西2026范本对应的包是按2020版做的，投标人须知约四成段落有变化。
2. 招标菜单、投标菜单、扫描件、未变的段落沿用旧包的设置、埋点和名称，不重新命名。
3. 差异归为四类，写入变更清单：新增、删除、字段变化、条件变化。
4. 只对变化部分重新判断，其余照搬。
   - 新版把空位改成“详见招标公告”之类引用的，删掉旧控件。
   - 新版增减了证明材料要求的，同步增减扫描件。
   - 新版章号变化的，同步检查替换标记名称。

## 十三、字典更新

资料包按“平台＋地区”各一套，不要合并：同一概念在不同平台的代码、类型值、形态都可能不同。

- 新平台第一次使用时，用它的一个现成结构化包生成资料包。
- 工具里的枚举值、扫描件目录有增减，或确认了某个枚举与读包代码的对应时，同步修改第五、六节的对照表。

切分结果经用户确认后，提醒用户把以下新增内容追加进对应资料包，下次沿用：字段代码、条件标记名、节点、个性化扫描件、html。字典里同一代码只保留一种含义。

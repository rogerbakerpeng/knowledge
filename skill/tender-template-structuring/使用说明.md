# tender-template-structuring 使用说明

> 技能全名：`tender-template-structuring`（招标范本结构化切分）
> 技能定义：[SKILL.md](SKILL.md)（746 行，含全部规则、枚举与代码，可整体加载）
> 原始包：[原始材料/tender-template-structuring.zip](原始材料/tender-template-structuring.zip)（SHA256 前缀 25596E4D）

## 一句话

把一份招标文件范本（Word）切成招标工具能导入的结构化素材：**代理端招标菜单 + 标记埋点清单、投标人端投标菜单节点 + html/Word、扫描件清单**。

## 什么时候用

- 拿到一份新范本，需要出切分清单和 html 供导入招标工具；
- 范本换版，需要对比旧版结构化包、只对变化部分重新判断；
- 想知道范本里哪些空位该埋控件、哪些不该。

## 三种场景（技能会自动判断并在结果开头写明）

| 场景 | 特征 | 做法 |
|---|---|---|
| A 已批注范本 | 范本有业务批注或空格处写字段代码 | 批注和代码就是埋点依据 |
| B 原始范本 | 没批注没代码 | 按内置规则 + 置信度分档识别空位（高置信直接埋，中置信列需确认清单） |
| C 换版 | 有旧版结构化包 | 读旧包自检，只对变化部分重新判断 |

## 输入 / 输出

**输入**：待切分范本（.doc/.docx）＋ 参考资料包（切分字典、html 模板库，按"平台+地区"选）＋ 可选旧版结构化包。

**输出**：
1. 切分结果工作簿 .xlsx（需确认清单、招标菜单、投标菜单、扫描件、标记埋点清单、字段字典、开标一览表字段、自检结果等表，枚举列带下拉验证）
2. 带标记文字的 Word 底稿（范本副本插标记、空位换占位文字）
3. 每个 html 节点一个文件 + 同名 Word 版本，打包压缩包
4. 回复正文：场景说明 → 数量概览 → 需确认清单要点 → "导入前必做事项"

## 工作方式要点

- **默认直接出结果，拿不准才提示**：只有"招标类型和评标办法范围无法判断且影响整体结构"这一种情况先问，其余先做完再集中列需确认清单。
- 枚举一律写工具下拉里的**中文名称**，不写代码；代码只在读旧包时用来还原。
- 材料读完之前不写输出；范本很长，**分章处理**，不整本一次判断。
- 条件标记的触发逻辑写在程序里，技能只负责埋点、命名、写明触发含义。
- 评标办法默认只留"内容替换标记"不切内容（广东包例外：整章原文保留，按资料包）。

## 规则来源与边界

规则提炼自四套已切好的范本：**佛山通用 3.0**（已批注、字段代码齐全）、**广西检测 2026**（公告取业务公告口径）、**湖南工程总承包 2024**（勾选保留型）、**广东智能辅助评标 1.09**（评标办法整章保留、标书类别最全）。包间差异大的地方都标了"按资料包"。

注意：导入工具前必须按"导入前必做事项"在制作工具里插入控件和标记（底稿里的标记只是定位文字，系统不识别），新增字段代码需确认，条件标记触发逻辑交开发实现，最后生成招标文件+答疑文件核对。

## 安装到本机 Codex

把 `tender-template-structuring/` 整个文件夹复制到 `$CODEX_HOME/skills/`（Windows 默认 `C:\Users\<用户名>\.codex\skills\`），文件夹名与技能 name 字段一致。见 [技能索引](../index.md)。

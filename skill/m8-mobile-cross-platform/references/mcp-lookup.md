# MCP 查询

`epoint-mrc-mcp` 提供 EM Components、Util 和 EJS-JSSDK 的动态文档。静态 skill 用于选择方向，MCP 或目标依赖源码用于确认精确接口。动态服务可能面向最新版本，不保证结果天然兼容 M8.3。

## 何时必须查询

- 不确定使用哪个 EM 组件、Util 方法或 EJS API。
- 第一次在目标工程使用某个组件/API。
- 需要确认属性类型、事件载荷、插槽、默认值、返回结构或支持平台。
- 静态知识、目标工程用例与 TypeScript 类型不一致。
- API 涉及位置、相机、媒体、文件、扫码、导航或其他容器能力。

简单的 Vue/Vuex/Pinia 语法、现有业务封装或目标工程中已经有完全相同用法时，无需为了形式重复查询。

## 查询流程

1. 先确认当前会话是否已连接 `epoint-mrc-mcp` 或暴露同类工具。
2. 不知道准确名称时先查列表，按需求筛选候选项。
3. 使用列表返回的有效名称查询详情，不凭猜测拼路径。
4. 查询时明确当前是 M8.3 还是 M8.4，记录属性、事件、插槽、参数、返回值、平台支持和最低版本。
5. 对照目标工程锁定包版本与类型/源码；动态服务若对应更高版本，不能直接使用新接口。
6. 根据核实结果编码，并让类型检查和目标端构建再次验证。

## 工具语义

实际工具名称可能带 MCP server 前缀，以当前会话暴露的名称为准。

| 逻辑工具 | 用途 | 典型参数 |
|---|---|---|
| `get_m8_ui_list` | 获取 EM 组件列表 | 无 |
| `get_m8_ui_info` | 获取组件属性、事件、插槽、示例 | `componentName`，如 `em-button` |
| `get_m8_util_list` | 获取 Util 方法列表 | 无 |
| `get_m8_util_info` | 获取 Util 参数、返回值和示例 | `utilName`，如 `ajax` |
| `get_ejs_api_list` | 获取 EJS-JSSDK API 列表 | 无 |
| `get_ejs_api_info` | 获取 EJS API、平台和示例 | `apiName`，如 `ui.confirm` |

详情工具通常要求使用列表返回的有效名称，因此默认遵循“list -> info”。当准确名称已由目标工程源码或用户提供，且工具允许直接详情查询时，可以跳过列表。

## 查询示例

日期选择需求：

1. 调用 UI 列表，筛选 date/calendar/picker 候选。
2. 查询候选组件详情。
3. 比较日期粒度、`v-model` 形式、确认/取消事件、最小最大日期和目标端支持。
4. 选择满足需求且项目已有风格最接近的组件。

文件上传需求：

1. 查询 `em-uploader`，确认选择结果结构和事件。
2. 查询 `Util.upload`，确认 `filePath`/`files`、进度、附加表单和错误回调。
3. 检查目标端临时文件结构，设计组件结果到上传参数的适配。

原生确认框需求：

1. 查询 EJS API 列表中的 UI 类能力。
2. 查询准确 API 详情，不混用静态文档中可能不同版本的 `confirm`、`showModal` 等命名。
3. 确认容器外降级方案和按钮返回值语义。

## MCP 不可用时

按以下优先级取证：

1. 目标业务工程中相同版本、相同 API 的现有用法。
2. M8.4 优先检查 `node_modules` 中对应包的 `.d.ts`、源码和随包文档；M8.3 也检查源码和版本变更记录。
3. 目标工程内部组件示例模块，例如 showcase。
4. 同版本 `m8mpdoc` 原文。
5. 本 skill 的静态概览。

仍无法确认关键参数时，应说明缺少依据并向用户确认或限制实现范围，不能造出看似合理的接口。

## 可选安装信息

知识库给出的服务包为：

```bash
npm install -g epoint-mrc-mcp
```

也可由客户端通过 `npx -y epoint-mrc-mcp` 启动。是否安装、如何注册 server 取决于当前 Agent 客户端和公司环境；不要在用户未要求配置 MCP 时擅自修改全局环境。

## 二、安装

**全局（所有项目可用）**

```bash
cp -R ~/Desktop/yuanskill-pro ~/.claude/skills/yuanskill-pro
```

**只给某个项目用**

```bash
mkdir -p /你的项目/.claude/skills
cp -R ~/Desktop/yuanskill-pro /你的项目/.claude/skills/yuanskill-pro
```

装完新开一个会话生效。

### ⚠️ 装之前先处理触发冲突

你本机已装 **60+ 个 skill**，其中两个与本技能语义高度重叠：

| 冲突对象 | 情况 | 建议 |
|---|---|---|
| `yuanskill`（v1，已装在 `~/.claude/skills/yuanskill`） | **已实测：两者同时存在时，说"我有段 prompt 想认真打磨一下"会触发旧版 v1，不是 pro** | **必须二选一。**把 v1 移出技能目录留作对照：`mv ~/.claude/skills/yuanskill ~/Desktop/yuanskill-v1-备份`（源目录 `~/polaris/yuanskill/` 保留不动）。不想动 v1 就每次点名调用 `/yuanskill-pro` |
| `skill-creator`（Anthropic 官方） | 它做"从零创建 skill / 跑 eval / 优化 description"，与本技能有真实重叠 | 不必卸载，按用途分工：**要脚手架和官方 eval 工具链 → skill-creator；要研究驱动的深度优化与重构 → yuanskill-pro**。不确定时直接点名调用 |

### 两条硬要求（改动时别踩）

1. **文件夹名必须是 `yuanskill-pro`**，与 `SKILL.md` 里的 `name: yuanskill-pro` 一致，否则不会被识别。
2. 顶部 YAML frontmatter 不能删；正文用相对路径引用 `references/` 与 `assets/`，目录名与文件名不能改。

## 三、怎么用

遇到这类需求，**先走本流程，不要随手改**：

> 优化提示词 / 完善 prompt / 设计或改进一个 skill / 让某段 prompt 效果更好 / 做 meta-prompt / prompt engineering / 打磨技能

也可以点名调用：`/yuanskill-pro`。

它会先判复杂度并**告知你选了哪种模式（可否决）**：

- **BASIC 快修**：走 `0 → 0.5 → 5 → 7`，交付「优化后产物 + 关键改动 + **一次基线对比结论** + 1–3 条使用提示」。
- **DETAIL 全流程**：走完 0→8，动手前先问 2–3 个关键问题，交付 9 件（含形态判定结论、对比取舍表、配套工程、**评测结果**、变化清单）。

### 相对 v1，你会明显感觉到的三个变化

1. **它会先问"这该不该做成 skill"** —— 可能直接告诉你"这件事放 CLAUDE.md 全局配置就行，别做技能"。这是阶段 0.5，是故意的。
2. **它不再只靠自审交付** —— 会要求跑一次「有产物 / 无产物」对比，用数据说明值不值得维护。评的不是绝对分，是相对裸跑提升了多少。
3. **产物是 skill 时会过一遍字段级工程** —— description 触发公式、三层渐进式披露、正文体量上限、引用只一层。

## 四、其它平台

所有文件都是纯 Markdown，不依赖脚本或外部资源，遵循 Agent Skills 开放标准。若目标平台不支持 skill 机制，直接把 `SKILL.md` 全文当提示词、把 `references/` 当知识库喂进去也能用。
